# Проект: Проектирование структуры БД и REST API для сервиса рассрочек 

Технический проект по разработке реляционной структуры базы данных и контрактов интеграции для финтех-модуля рассрочек (деление суммы покупки на 4 равных платежа).

## Стек технологий и методология
* **СУБД:** PostgreSQL
* **Инструмент проектирования:** DBeaver CE
* **Интеграция:** REST API, JSON, архитектура клиент-сервер
* **Нормализация:** 3NF (Третья нормальная форма)

## 1. Архитектура базы данных (ER-диаграмма)

База данных спроектирована в третьей нормальной форме (3NF) для обеспечения ссылочной целостности и исключения аномалий при обновлении данных.

![ER-диаграмма проекта](image.png)

### Структура таблиц и логика ограничений:
1. **`users` (Пользователи)** — хранит персональные данные клиентов. Связь с таблицей заказов: **1:M (Один ко многим)**.
2. **`orders` (Заказы)** — фиксирует общую сумму рассрочки и торговую точку (`merchant_name`). Поле `user_id` является внешним ключом (`FOREIGN KEY`). Ограничение `ON DELETE RESTRICT` запрещает удалять пользователя, если у него есть активные заказы.
3. **`payment_schedule` (График долей)** — хранит информацию о 4-х платежах для каждого заказа (связь **1:M**). Ограничение `ON DELETE CASCADE` автоматически очищает график при аннулировании заказа. Для финансовых сумм используется тип с фиксированной точностью `NUMERIC(10, 2)`, предотвращающий ошибки округления.

## 2. Спецификация REST API (Контракт интеграции)

Чтобы мобильное приложение могло взаимодействовать со спроектированной базой данных, разработан контракт для метода оформления рассрочки.

### Метод создания заказа и расчета графика
* **HTTP-метод:** `POST` (создание новой сущности)
* **Эндпоинт (URL):** `/api/v1/installments/orders`

#### Пример запроса от мобильного приложения (Request Body в формате JSON):
```json
{
  "user_id": 1,
  "total_amount": 12000.00,
  "merchant_name": "OZON"
}
```

#### Пример успешного ответа сервера (Response `201 Created`):
```json
{
  "order_id": 1,
  "status": "ACTIVE",
  "first_payment_amount": 3000.00,
  "next_payment_date": "2026-10-29"
}
```

### Обработка негативных сценариев:
1. **Пользователь не найден в базе данных (`400 Bad Request`):**
   Если передан `user_id`, отсутствующий в таблице `users`.
   ```json
   {
     "error_code": "USER_NOT_FOUND",
     "message": "Пользователь с указанным ID не зарегистрирован"
   }
   ```
2. **Ошибка первой оплаты (`422 Unprocessable Entity`):**
   По условиям сервиса первая доля (3000 руб.) списывается сразу. Если на карте клиента нет денег, рассрочка не оформляется.
   ```json
   {
     "error_code": "INSUFFICIENT_FUNDS",
     "message": "Недостаточно средств для списания первой доли платежа"
   }
   ```

## 3. Структура файлов и развертывание
* **`Table.sql`** — DDL-скрипт создания структуры таблиц и внешних ключей.
* **`Data.sql`** — DML-скрипт наполнения таблиц тестовыми верификационными данными и демонстрации логики транзакций.
* **`image.png`** — визуализация схемы данных (ER-диаграмма), сгенерированная из DBeaver.

### Порядок локального запуска:
1. Выполнить скрипт `Table.sql` целиком (`Alt + X` в DBeaver).
2. Выполнить скрипт `Data.sql` целиком (`Alt + X` в DBeaver).
